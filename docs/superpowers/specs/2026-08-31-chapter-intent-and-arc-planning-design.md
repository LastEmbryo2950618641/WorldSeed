# 创作台章节意图控件与弧线规划设计

> **状态：** 已确认可实施（2026-08-31）；开放决策按 §3 推荐锁定  
> **实施顺序：** 先写 P0 实现计划并落地，再 P1（弧线/连续/监视交接），P2 后置  

> **范围：** 创作台工具栏新增「边界节奏」「因果焦点」；讨论期可产出弧线大纲与有限预建梗概；正式推演仍一章一轮；**讨论 Agent 可只读监控推演过程，并在推演完成后收到后台交接通知。**  
> **关联：** [剧情梗概讨论](./2026-08-27-plot-synopsis-discussion-design.md) · [暂存区](./2026-08-30-synopsis-staging-area-design.md) · [推演目标](./2026-08-27-creation-desk-deduction-goals-design.md) · 项目设置 `worldDivergenceMode`  
> **评估：** 三路并行评审（产品、创作台 UI/载荷、多章梗概技术）后综合；**不建议原样实现用户初稿全部字面语义**，见 §2。

## 1. 用户目标

作者在创作台（梗概讨论）希望：

1. **单章意图旋钮**：在「描写 / 笔风 / 字数」旁增加两个可选下拉，约束本章讨论与后续正式推演的叙事边界与因果描写重心；
2. **讨论感知**：Agent 在梗概讨论中也知晓当前旋钮，并据此建议、改写梗概；
3. **弧线规划**：讨论一段故事时，Agent 可判断「当前这段写不完一章 / 需要多章」，建议合理字数与章数，**先落大纲**；后续各章正式推演再接着写；
4. **跨推演连续讨论**：正式推演与创作台讨论是**两套上下文**；推演结束后回到讨论时，**暂存区与讨论连续性不得断掉**，可基于同一弧线继续改大纲与下一章梗概；
5. **讨论 Agent 督导推演**：讨论 Agent 相当于「更全能」的编排者——可**只读监控**推演 Agent 各阶段结果与相关上下文；正式推演**完成后**由系统**后台通知**讨论 Agent，并告知正文落成情况，便于它更新大纲/暂存/下一章建议（无需用户手工复述推演结果）。

**非目标（本设计明确不做）：**

- 不与项目级「推演发散程度」合并为同一控件（设定创造 ≠ 情节节奏）；
- 不在 MVP 批量预建大量「权威可推演」梗概并默认长期有效；
- 不做机械 NLP 校验「是否违反强约束」（成本高、误报多）；靠提示词附录 + 用户审梗概；
- 不改变 turn orchestrator「一章一轮」执行模型；
- **不把正式推演的 phase/KV 链与创作台讨论链混成同一条可写模型上下文**（见 §6.7）；讨论侧对推演侧是 **观察 + 交接，不是共享同一条对话链**；
- MVP **不**让讨论 Agent 在推演中途抢控 / 改写正在跑的 phase（只读监控；干预仍走用户检查点）。

## 2. 多 Agent 评估结论

| 维度 | 结论 |
| --- | --- |
| 工具栏两下拉 | **可行（高）**，与现有 `creation-desk-settings` 同构 |
| 讨论态也带上设置 | **可行（中高）**，需扩展 `synopsis.conversation.send` / `beginTurn` 载荷（今日 `presentation` 主要进 beginTurn） |
| 正式推演强制执行 | **中**：仿 `worldDivergencePhaseAppendix` 注入 draft 等阶段；无现成校验器 |
| 多章大纲 + 预建梗概 | **中低～中**：文件系统允许多个 `[剧情梗概].md`；缺口是 `start()` 不认领已有文件、会话模型偏「下一章单 active」 |
| 产品文案原案 | **需重塑**：原「强约束禁止角色做决定」叙事上不成立；因果任意组合认知过重；批量完整梗概易成陈旧计划债 |
| 讨论监视推演 + 完成后交接 | **可行（中）**：复用 `turn.status`/`phaseRuns` 做只读投影；完成后 handoff brief → 弧讨论系统消息；完整逐步上下文需裁剪，不宜默认灌满 |

**综合建议：** A（两控件）**重塑后上线**；B（多章）**轻量大纲 + 有限预建**；C（监视/交接）**P1 上只读摘要监视 + 完成后交接**，拒绝混写链与中途抢控。

| 推演完成交接 | 后台 `TurnHandoffBrief` → 系统消息 + 可选自动分析 |
| 推演过程监控 | MVP **只读阶段摘要**；完整逐步上下文 → P2 |
| 推演完成后自动分析 | **默认开、可关**（开关 UI 可落 P2；P1 先默认开） |

## 4. 控件 A：边界节奏（原「边界设置」）

### 4.1 放置

`SynopsisConversationComposer` 的 `creation-desk-settings` 行，在「字数」附近新增：

```text
边界节奏: [ 可推进（仍贴梗概) ▾ ]
因果焦点: [ 自动 ▾ ]
```

（`ChapterConversationComposer` 修订对话**不**加这两项。）

### 4.2 选项与语义

| 值 | UI 文案 | 讨论期含义 | 正式推演含义 |
| --- | --- | --- | --- |
| `advance_allowed`（默认） | 可推进（仍贴梗概） | 可设计章内合理行动与阶段性结果，不得无故违背已定梗概 | draft 可写局部后果；仍须贴梗概与设定边界 |
| `hold_without_resolution` | 压而不决 | 加压、揭示、逼近抉择；**不落地不可逆结果**；可写过程性选择 | 禁止章末定生死/定关系/完成终极目标等闭合结局 |

**显式禁止（产品文案，写入提示附录）：**

- 把「压而不决」理解成「角色不能做任何决定」——**错误**；
- 用本控件替代「推演发散程度」去管新设定——**错误**。

**与梗概的关系：** 「必须大体待在梗概范围内」是**两条选项的共同默认**；控件差在「本章能不能收束」。

### 4.3 载荷

扩展讨论与推演共用的意图结构（命名实现时可落在 `presentation` 旁或并入）：

```ts
type ChapterNarrativeIntent = Readonly<{
  boundaryPace: "advance_allowed" | "hold_without_resolution"
  causalityFocus: "auto" | "buildup" | "action" | "payoff"
}>
```

- `synopsis.conversation.send` / `beginTurn`：必须携带当前 UI 值；
- `turn.start`（若从创作台发起）：同样携带；
- 注入方式：仿 `worldDivergencePhaseAppendix`，为 `synopsis_discuss` 与 `draft`（必要时 `semantic_review`）追加可读附录。

### 4.4 默认与持久化

- 默认：`advance_allowed` + `auto`；
- MVP：仅 renderer 会话态（与描写/笔风/字数一致）；
- Later：可写入每章 session 元数据或梗概 front-matter，便于重开恢复。

## 5. 控件 B：因果焦点（原「因果设置」）

### 5.1 为何不做成「前因/行动/后果」全组合

全组合约 8 态，作者认知负担高，且与字数、跨章切分纠缠。改为**写作意图单选**：

| 值 | UI 文案 | 含义 |
| --- | --- | --- |
| `auto`（默认） | 自动 | Agent 按梗概与上下文分配前因/行动/后果比重；任一阶段过重可建议拆到后续章 |
| `buildup` | 蓄势 | 偏前因、压力、信息铺垫 |
| `action` | 行动 | 偏过程、对抗、旅途、交锋 |
| `payoff` | 落点 | 偏后果、阶段性收束（仍受边界节奏约束；若为「压而不决」则只允许可逆/局部落点） |

进阶微调（「多写后果、少写前因」）留给**自然语言讨论**，不占下拉。

### 5.2 「自动」与跨章

- Agent 可在讨论中建议：「前因需两章，本章只写蓄势」；
- 建议落入**弧大纲 / 章目的**，不自动改用户未确认的多章文件（MVP）。

## 6. 能力 B：弧线规划、有限预建与讨论连续性

### 6.1 产品形态（含「写不完先落大纲」）

讨论中用户可要求，或 Agent 主动判断并建议：

> 「这段按当前字数目标没法一次性写完；更合理是约 X 千字、分 Y 章。可以先落大纲，后面再一章章推演接着写。」

标准产物：

1. **弧大纲**：这段故事的目标、节拍、建议总字数区间、建议章数；
2. **章目的列表**：每章一句话（不是完整梗概）；
3. **物化文件（MVP 上限）**：
   - 必选：为**当前下一章**（`nextSequence`）写入/更新正式 `[剧情梗概].md`（现有行为）；
   - 可选：额外预建 **至多 1 章**（`nextSequence+1`）草稿梗概；
   - 更远章节：只留在大纲里的「章目的」，**不落盘完整梗概**。

正式推演：仍 `beginTurn` → 单章 turn；不得一次推演多章。推演完一章后，回到创作台**继续同一弧线的讨论**，再准备下一章梗概并推演。

### 6.2 存储（MVP）

| 内容 | 位置 | 推演后 |
| --- | --- | --- |
| 弧大纲 + 章目的 | `暂存区/弧线规划.md`（MVP 优先暂存区） | **保留**；标记已完成章，更新「当前写到」 |
| 本章讨论笔记等暂存 | `暂存区/*.md`（现有固定文件） | **保留**；可读可改；不得因 `linkAfterPublish` 删除 |
| 当前章梗概 | `章节正文/第N章 … [剧情梗概].md` + 章 session | 发布后仍按现有规则归档进 DB 并移出工作区 |
| 预建下一章草稿梗概 | 同目录 `第N+1章 … [剧情梗概].md` | **保留**；可标「可能过期」 |

### 6.3 认领规则（关键缺口）

`synopsis` 打开下一章讨论时：

1. `nextSequence = max(committed)+1`；
2. 若工作区已存在该 sequence 的 `[剧情梗概].md` → **挂接**，勿用空白「待命名」覆盖；
3. 若不存在 → 现有占位创建逻辑；
4. 同时确保讨论 UI 仍能读到 **弧讨论连续性**（§6.7）与全部 `暂存区/`。

### 6.4 过期与修订

- 第 N 章正式推演并发布后：弧大纲中 N 标记完成；**N+1 及更远**可标「可能过期」；
- 不自动重写全部后续梗概；用户可在**同一讨论连续性**中要求「按本章正文结果刷新下一章梗概 / 大纲」；
- 未推演梗概文件与大纲始终可手改。

### 6.5 与推演目标

- 讨论确认后，可为 N..N+k 写 **planned** 进度；
- **禁止**对未开始章 `lockForTurn`；
- 本轮 turn 只 lock 当前章。

### 6.6 Later（明确延期）

- 批量预建 N>2 完整梗概 + 队列 UI；
- 多条并行弧线（多线程）；
- 章后自动改写后续全部梗概；
- 大纲版本树 / 一等公民 DB 表。

### 6.7 双上下文模型（硬约束）

```text
┌─────────────────────────────┐     ┌─────────────────────────────┐
│ 创作台讨论 Agent（编排/全能） │     │ 正式推演 Agent（执行）        │
│ synopsis_discuss            │     │ turn phases (draft…)        │
│ + 弧讨论消息持久化            │     │ + turn model context chain  │
│ + 可读：暂存区 / 弧大纲       │     │ + 本章梗概全文作 userInput   │
│ + 可读：设定集 / 已发布章     │     │ + 图 / 检索 / 目标 lock      │
│ + 只读：推演监视投影（§6.9）  │◄─obs─│ phaseRuns / 公开快照         │
│ 禁止：直接写正式章正文        │     │ 禁止：复用讨论 KV/phase 视图 │
└─────────────────────────────┘     └─────────────────────────────┘
              │                                      │
              │  beginTurn：只交接梗概（+短弧位置）    │
              │  讨论线程继续存在                      │
              │                                      │
              │◄──── 完成后台交接通知（§6.9）──────────┘
              ▼
     更新大纲/暂存/下一章建议；用户可继续讨论
```

**分离：**

- 讨论与推演使用**不同**的 `contextViewRef` / task 作用域；推演启动**不得**把 `synopsis-discuss:…` 链当作 turn 的父链继续 append。
- `beginTurn` 的引导输入仍以**当前章梗概文件全文**为主；需要时另加极短的「弧位置」摘要，**不是**整段讨论 transcript，也**不是**推演监视日志全文。

**连续（讨论侧）：**

| 机制 | MVP 要求 |
| --- | --- |
| **暂存区** | 跨章、跨推演持久；publish 不得删除 |
| **弧线规划.md** | 弧级记忆文件真相源 |
| **弧讨论线程** | 跨章共享消息流；章 session 只绑当前章号/梗概 path |
| **推演后** | 章可标 completed；UI 进下一章准备态，历史仍可见 |

**观察 ≠ 合流：** 讨论 Agent「看得见」推演，不等于两边共享同一条可写对话；监视数据以**投影/摘要**进入讨论侧（系统消息、暂存区、工具可读快照），避免把整条 turn KV 灌进讨论链导致爆上下文与串味。

### 6.8 Agent 话术约定（大纲优先）

当用户描述的情节或因果焦点明显超出单章字数预算时，Agent **应优先**：

1. 给出预估（约多少字、几章更合理）；  
2. 给出「先落大纲 / 仍强行压进本章」选项；  
3. 用户确认「先落大纲」后再写 `arcPlan` 并更新 `暂存区/弧线规划.md`；  
4. 再为当前章写可推演的一章梗概（可配合「压而不决 / 蓄势」等意图）。

### 6.9 讨论 Agent 监视推演与完成后交接

目标：讨论 Agent 是**编排者**（知道弧线、暂存、用户意图），推演 Agent 是**执行者**（按梗概写正文）；编排者能盯执行过程，并在收工后自动拿到结果，而不是让用户当传话筒。

#### 6.9.1 运行中：只读监视（live）

| 能力 | MVP | 说明 |
| --- | --- | --- |
| 订阅推演进度 | 是 | 复用现有 `turn.status` / `phaseRuns` / RightRail 同源公开投影 |
| 讨论 Agent 主动「查看当前推演」 | 是 | 作为 `synopsis_discuss` 的**只读工具/证据源**（如 `sourceKinds: turn_monitor` 或专用 port），返回阶段名、状态、短摘要、关键 artifact 指针 |
| 看见每步完整模型上下文 | **否（默认）** | 完整 turn 上下文体积大、含检索原文；MVP 只给**阶段结果摘要 + 关键字段**（章稿片段上限、设定抽取条数、图变更计数等） |
| 看见逐步完整上下文 | Later / 显式展开 | 「高级监视」按 phase 拉取裁剪后的 context digest，仍只读、不写入 turn 链 |
| 中途改写推演 | 否 | 暂停/重试/回退仍走用户检查点；讨论 Agent 可**建议**用户点什么，不得静默 `turn.resume` |

UI（可选 P1）：创作台旁「推演监视」折叠面板，与讨论气泡同步显示阶段；不强制每次模型调用都 ingest 全量监视日志。

#### 6.9.2 完成后：后台交接通知（handoff）

触发点：turn **成功发布正文**之后（`chapter_publisher` + `linkAfterPublish` 成功；与现有 post-commit 时机对齐）。失败/回退**不**发「正文如何」成功交接，可另发简短「推演未完成」系统事件。

后台流水（不阻塞用户关检查点）：

1. 组装 `TurnHandoffBrief`（结构化，可测）：
   - `taskId` / `chapterSequence` / `chapterPath` / `chapterHeading`
   - 正文摘要（截断 + 结构要点，非整章默认塞进模型）
   - 相对开推前梗概的偏差/兑现要点（短列表）
   - 设定抽取/暂存相关已发生变更的指针（若有）
   - 弧位置：大纲中本章目的是否视为完成
2. 写入弧讨论一条 **role=system（或 assistant-system）** 消息：「第 N 章已推演完成……」+ brief 摘要；
3. **可选自动一轮** `synopsis_discuss`（`trigger: turn_handoff`，无用户输入）：
   - 允许更新 `暂存区/弧线规划.md`、本章讨论笔记、提议下一章梗概修订；
   - **禁止**自动 `beginTurn`；
   - 用户可在设置关闭「推演完成后自动分析」（**默认开、可关**；开关 UI 可 P2，P1 先按默认开实现）。
4. UI：创作台出现「推演完成 · 讨论 Agent 已收到交接」提示；用户回到创作台即可看到系统消息与后续建议。

#### 6.9.3 「全能」边界（避免误解）

讨论 Agent **全能**指：

- 掌握弧线、暂存、用户意图、历史讨论；
- 能观察推演公开进度与交接 brief；
- 能据此规划下一章。

讨论 Agent **不能**：

- 与推演共享同一条可写 KV 链；
- MVP 静默接管 turn；
- 默认把每一步完整检索原文/完整 draft 无裁剪灌进讨论上下文（需摘要与上限）。

#### 6.9.4 数据与权限

```ts
type TurnMonitorPhaseSnapshot = Readonly<{
  phase: string
  status: string
  summary: string           // 短摘要，有硬上限
  artifactRef?: string      // 可选指针，按需再读
  finishedAtMs?: number
}>

type TurnHandoffBrief = Readonly<{
  taskId: string
  chapterSequence: number
  chapterPath: string
  chapterHeading: string
  bodyDigest: string        // 摘要，非整章默认
  outlineNotes: readonly string[]
  createdAtMs: number
}>
```

- 监视与交接均走**应用层投影**，不直接把 utility 进程内存里的 private chain 暴露给 renderer 任意读取；
- 同一 `projectId` 仅绑定当前弧讨论线程接收 handoff。

## 7. 与现有系统的关系

```text
项目设置 worldDivergenceMode     ← 设定能否新造
创作台 chapterIntent             ← 本章情节节奏  【本设计】
弧讨论线程 + 暂存区/弧线规划.md   ← 跨章讨论连续性与弧地图  【本设计】
章 session + 梗概文件            ← 下一章权威推演输入（与讨论链分离）
deduction goals                  ← 跨章目标计划
turn orchestrator                ← 仍一章一轮；独立上下文
```

优先级（冲突时）：

1. 用户已确认的梗概正文与设定集；  
2. 本章 `chapterIntent` 附录；  
3. 项目 `worldDivergenceMode`；  
4. 弧大纲中的远期章目的（仅指导，非权威）。

## 8. 实现分期

### P0 — 章节意图控件（建议先做）

1. UI：两下拉 + 默认值 + 简短 tooltip；  
2. 类型与 contracts：`ChapterNarrativeIntent`；send / beginTurn / turn.start 贯通；  
3. Prompt 附录：`synopsis_discuss` + `draft`；  
4. Fake adapter / 测试：载荷透传与附录存在性。

### P1 — 弧线规划 + 讨论连续性 + 推演监视/交接

1. Discuss artifact：`arcPlan` + 「先落大纲」确认选项；写入 `暂存区/弧线规划.md`；  
2. **暂存区跨发布保留**审计；  
3. **弧讨论连续性**（`arc_thread_id` 或合并 list）；  
4. `start` 认领已有 synopsis 文件；  
5. **Turn 监视投影** + 讨论侧只读工具；  
6. **完成后 handoff**：`TurnHandoffBrief` → 弧讨论系统消息 + 可选自动 `synopsis_discuss(trigger: turn_handoff)`；  
7. 硬约束测试：beginTurn **不**继承讨论 contextViewRef；handoff **不**自动 beginTurn。

### P2 — 体验加固

1. 过期提示与「按正文刷新下一章梗概」；  
2. Intent 写入 session/front-matter；  
3. 与 goals 的一键对齐；  
4. 高级监视：按需拉取裁剪后的 phase context digest；  
5. 「推演完成后自动分析」用户开关。

## 9. 风险与开放问题

| 风险 | 缓解 |
| --- | --- |
| 与「推演发散」文案混淆 | 明确旁注；设置页与创作台用词分离 |
| 「压而不决」被写成空章 | 附录白名单：允许加压、揭示、过程选择 |
| 预建梗概过期 | MVP 限制预建数量；过期提示；不自动权威化 |
| start 覆盖已有文件 | P1 认领规则为硬条件 |
| 推演后讨论「失忆」 | 弧线程 + 暂存区硬保留（§6.7） |
| 讨论/推演上下文串味 | 禁止共用可写 contextViewRef；测试锁定 |
| 监视灌爆讨论上下文 | 只摘要 + 上限；完整上下文 Later 按需 |
| handoff 打扰 / 费 token | 可关自动分析；brief 截断 |
| 工具栏过挤 | 小屏可折行；文案短；tooltip 承载定义 |

**开放问题：** 已全部按 §3 锁定；实施中若发现与现网行为冲突，改本 spec 后再改代码。

## 10. 成功标准

- 作者能在讨论中改变两旋钮，并在 Agent 回复中体现；  
- 正式推演 draft 提示中可见对应附录；  
- 情节过长时 Agent 会建议预估字数/章数并「先落大纲」；  
- 规划本弧后，`暂存区/弧线规划.md` 存在；`nextSequence` 已有梗概时不被空白占位覆盖；  
- **推演发布后**再开发作台：暂存区内容仍在，讨论历史仍可接着聊同一弧；  
- 推演进行中讨论侧可看到阶段监视；完成后自动出现交接系统消息（及可选自动分析）；  
- 推演仍严格一章一轮；讨论与 turn **可写上下文分离**（可测）；监视只读。
