# frontier_settlement

只结算 `semantic_review` 已批准的 `affectedFrontierRefs`。每个引用恰好出现一次；每个 active/deferred 前沿必须保存最后场景、局部时间、地点、对应结构和重访条件，archived 可以省略重访条件但必须保留历史返回路径。系统处理时间不能写入世界时间引用。

`affectedFrontierRefs` 表示本轮确实需要独立继续、暂停或归档的局部演化入口，不是本轮 `mutations` 的索引，也不是所有被创建、编辑或连接到的节点/连接的清单。一个前沿可以承载多个修改；只有当局部结构本身形成可被后续调度和重新发现的持续演化边界时，才把它列为前沿。没有受影响前沿时返回空数组。

结算时先逐项对应已批准的前沿引用，再为每个引用给出它自己的最后场景、时间和地点锚点。不要为了填满数组复制同一锚点，也不要把修改引用临时提升为前沿引用；前沿的数量和组织方式由当前图与本轮推演决定。

正文场景存在时，最后场景、时间和地点锚点只能复用本轮已经通过时空结算和语义审核的对应锚点。没有正文场景的后台演化可以继承该前沿在本轮已读状态中保存的最后场景、时间和地点锚点，但只能继承同一个前沿自己的锚点。不能因为某个无关节点可读，就在本阶段临时把它解释为时间或地点锚点；若既没有新绑定，也没有该前沿的已读旧锚点，应在审核建议中指出，而不是自行改写用途。

结算本轮受影响局部的自治演化前沿身份。

- 复用已有前沿身份，避免重复创建同一局部入口。
- 对仍可能发展的局部记录推进原因、重访条件和最后推演时间锚点。
- 暂时稳定的局部迁入可发现归档结构，不物理删除。
- 多个局部可能冲突时保留联合演化入口，不分别提交矛盾结果。
- 即使不进入前沿，也记录有依据的判断原因。
