# rule_assembly

根据基础规则和实际可见的项目资料形成不可变规则快照。

- 用户规则只在明确适用范围内优先，不是覆盖或修改基础规则。
- 设定集和参考资料提供内容依据，不冒充规则。
- 表现规则只控制正文如何表达，不自动改变世界事实。
- `selectedWorkspacePaths` 只能填写 `readEvidence` 中已经返回的工作区路径；平台基础规则通过独立静态版本锁定，不把工作区中的只读镜像路径加入该数组。
- 本阶段必须阅读并使用 `readEvidence` 中已注入的全部用户规则、`设定集/readme.md` 与 `参考文件/readme.md`，但这些内容只作为判断输入，绝不能复制到输出；不要在本阶段查询世界图事实。
- 设定集选择性读取遵循《设定集默认查询规则》：先索引、再精确路径、按任务片段读取，不把设定集当作规则层。
- 目录快照位于 `workspaceCatalog`。需要补读规则文件时使用 `sourceKinds: ["rule"]`，需要补读设定集或参考文件时使用 `sourceKinds: ["reference"]`，并优先给出目录中的精确 Markdown 路径。
- 记录每个选中工作区路径及选择原因；版本由后端从本轮实际读取证据解析，不能自行生成版本 ID；冲突无法解决时请求读取或保留冲突。
- `selectedWorkspacePaths` 只列一次实际选中的已读路径；`selectionReasons` 的键必须与该数组完全一致，每个理由只写一句，不复制文件内容、目录快照、读取证据或其他阶段 artifact。
- 本阶段没有正文或长文本字段；`selectionReasons`、`reason` 和 `selfReview` 都只写最短的单句结论，不能写规则解释、资料摘要、目录清单或推理过程。
- 只要没有新的规则选择或冲突，使用空数组和简短结论；不要为了表示“已完整阅读”而重复路径、证据或文件内容。
- 没有真实规则冲突时返回空的 `unresolvedRuleConflicts`。供应商允许的最大输出量只是故障边界，不是生成目标；本阶段结果应保持为满足契约所需的最小 JSON，禁止重复路径、理由、目录项或输入内容。
- 本阶段返回的是规则选择控制结果，不是规则、设定、参考资料或目录的复印件；完整性只表示选择结果闭合，不表示复述所有已读内容。
- 每个路径和冲突各只出现一次；没有新增选择或冲突时使用空数组，完成单个 JSON 对象后立即停止输出。
- 输出 `rule_assembly` 阶段结果包和对应 artifact。
