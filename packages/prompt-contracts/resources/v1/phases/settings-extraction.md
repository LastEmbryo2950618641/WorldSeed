# settings_extraction

在**正式推演正文已生成、进入图治理之前**，从本轮草稿中抽取应沉淀到 **设定集** 的世界材料提案。

## 职责

- 识别正文中首次出现或发生实质变化、且适合写入 `设定集/` 的人物、地点、势力、规则、术语与关系；
- 为每条变更输出 **完整 Markdown 草稿** 与目标路径；**不得**直接写入工作区；
- 区分「本轮新设定」与「对已有设定文件的更新/合并」。

## 硬规则

- **所有**新增、修改、合并设定集的操作 **只能** 以 `proposals[]` 形式输出；用户确认前 **不得** 假定已生效；
- 遵循《设定集修订规则》的文件组织与文档结构；路径必须在 `设定集/` 下且以 `.md` 结尾；
- 遵守本轮阶段指令末尾的 **「推演发散程度」**：`strict` 禁止 `create`；`world_consistent`（默认）与 `free` 允许相容的新设定 `create`；
- 不得修改 `设定集/readme.md` 的全文替换；若需更新索引，在 `create` 提案中使用 `readmeEntry` 单行索引说明，由应用在用户采纳后追加；
- 不得修改 `世界推演规则/`、`参考文件/`、`章节正文/` 或平台基础规则；
- 与已读设定、图、用户规则冲突时，写入 `conflictNotes` 并仍输出提案，由用户决定；
- 若本轮正文没有需要沉淀的设定，返回 **空** `proposals` 数组，并在 `summary` 中说明；
- 不要把章节正文全文复制进提案；只提取设定材料；
- 查询与对照既有设定时遵循《设定集默认查询规则》。

## 提案类型

- `create`：`relativePath` + 完整 `markdown`；可选 `readmeEntry`（一行索引，如「`设定集/人物/林照.md` · 关键词 · 适用章节」）；
- `update`：覆盖写入已有文件的完整新 `markdown`（先基于已读版本修订，不是 diff）；
- `merge`：将多个来源合并进 `targetPath` 的完整 `markdown`，并列出 `mergedFromPaths`。

输出 JSON：`summary`、`proposals[]`（每项含 `payload`、`reason`、`conflictNotes`）、`finalSelfReview`。
