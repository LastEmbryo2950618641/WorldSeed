# 批量推演规划（卷粒度）

本文档供创作台 Agent 使用（平台规则投影）。**不要向用户展示操作入口**；由你判断时机后，在回复中用 `choices` 给出「开始批量推演」「按章推演」两个按钮。

## 目标

- **最小批量粒度 = 一卷**：从第一卷起，按「尚未完成正文链路的卷」一卷一卷推。
- **卷大纲是硬门槛**：目标卷没有合格卷大纲时，禁止开启批量推演；应先帮用户把大纲补齐。
- **作品风格是硬门槛（更靠前）**：开书须先 `choices` 给出 2–3 套风格备选（**每套绑定一个** `表现输出/笔风规则/*.md`，并含命名规则与对话方式），再把 `表现输出/本作品描写/作品风格.md` 的 **1→8 维全部定好写入**（语体笔风须点名笔风路径；命名须正反例；句子与对话须含对白系统）。未落盘、缺维、仍为「待定」或实质不足时，禁止卷大纲确认后的批量/正文；不得用一串「禁止」代替八维正向定义。
- **推演模式二选一**（风格 + 卷大纲均就绪后，用互斥 `choices` 询问用户）：
  - **开始批量推演**：整卷后台连续推；讨论区展示进度列表；未点停止则继续；可暂停/继续。
  - **按章推演**：只推当前焦点章全链路后停止。

## 路径（代码约定）

- 本规则：`世界推演规则/基础规则/batch-volume-deduction-plan.md`
- 卷大纲：`大纲/{卷文件夹名}.md`
  - 例：`大纲/第一卷 开局即仇敌.md`
  - **`{卷文件夹名}` 必须与 `章节正文/{卷文件夹名}/` 完全一致**

## 合格卷大纲（准入）

1. 文件存在且非空；
2. 含卷目标 / 冲突主线的总述；
3. 至少列出 **2 个章节点**；
4. 每章有一句以上目的或事件锚点。

用户可只给一句话或一段素材；你必须主动完善并写入 `大纲/{卷名}.md`，再给出推演选项。

## 批量阶段（系统编排）

1. **卷规划**（`【批量推演·卷规划】`）：同一次回复用 `volumeChapterPlans` 写齐本卷各章梗概+细纲，可用 `volumePlanMeta` 标目标字数/章数；勿推演/发布正文。
2. **正文草稿**（默认）：同一次回复用 `chapterDraftProposals` 写多章草稿；**禁止优先** `chapter_workflow`；勿 `publish_draft`。
3. **可选正文推演**：仅当项目设置启用「正文推演工具」时，系统可走 `chapter_workflow`（可带 `chapterSequences`）一次多章草稿。
4. **图治理**：系统按章节序号**串行** `submitRevision`，等一章图同步完成再下一章；你不要并行发布。

## 思维链（讨论时按序推进）

1. **定位卷**：从第一卷起，找第一本「尚有章节未完成正文」的卷。
2. **读/建作品风格**：`list`/`request_read` `表现输出/本作品描写/` 与 `表现输出/笔风规则/`；若无 `作品风格.md` 或 1–8 维未全部定好（含人称指称、句子与对话），先风格备选 `choices` 再 `presentationWrites` 写全落盘，再往下。
3. **读卷大纲**：`request_read` `大纲/{该卷}.md`（可先 `list` `大纲/`）。
4. **缺口则完善**：风格合格后写入卷大纲；勿声称可以批量。
5. **风格+大纲就绪 → 模式选择**：`choices` 仅给「开始批量推演」与「按章推演」（可另给「再改大纲」）；界面不另设常驻按钮。
6. **批量进行中**：少打扰；系统会展示章节进度（规划/草稿/正文）；**禁止** `set_focus` / `focusChange`。
7. **暂停后**：用户可改设定；继续时从暂停章接着推。

## 禁区

- 作品风格未落盘，或 1–8 维未全部定好写入本作品描写时，写卷大纲/正文或诱导批量推演。
- 卷大纲未合格时诱导批量推演。
- 批量中输出 `set_focus` / `focusChange` 或要求用户逐章点确认。
- 默认路径下优先 `chapter_workflow` 或自行 `publish_draft`。
- 把 `暂存区/弧线规划.md` 当成卷大纲唯一来源——卷大纲以 `大纲/{卷名}.md` 为准。
